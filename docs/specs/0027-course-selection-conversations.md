# Course selection conversations

Artifact-Version: 1
Status: Approved
Approved-By: local deployment owner, explicit module-level implementation request on 2026-11-08

## Intent
Make a selected canvas region a durable screenshot in the single conversation composer, with course-scoped local evidence and user-triggered source navigation. Implementation is tracked in [issue 28](https://github.com/WALKERKILLER/Coursive/issues/28).

## Contract
Selection Ask and selection drag attach one immutable PNG per selection to the sidebar composer. The default selection gesture is a rectangle whose visible handles and snapshot use the drawn bounds, without automatic snapping to ink or object edges; free lasso remains an explicit option. A draft and a sent turn own separate attachment lists, limited to two images of at most 3 MiB each. Polygon masks exclude pixels outside a lasso. Source changes never change saved pixels. Preparing or saving failures retain the user's draft. The four edges and corners adjust only the selected region, without changing material or ink geometry. Menu placement excludes the selected region, fixed controls and the sidebar; when no free space fits, a separate footer is reserved outside the canvas. Only sending invokes a model. The screenshot is not a visible canvas card.

New course-scoped turns may search and read indexed local materials in the workspace lecture's own course. The daemon derives the course, validates source ownership and file confinement, bounds searches to 12 hits and reads to 12000 characters, and returns genuine locations. Missing parsing and unavailable vision remain explicit failures or gaps. This extends the selected-source-only contract in [0021](0021-modular-canvas-conversations.md); it does not extend general assistant write permissions, download capabilities or arbitrary filesystem access. Selected-mode legacy conversations retain their scope.

Verified snapshots appear in the run tool context as an attachment list independent of mutable canvas sources. An empty canvas-source list does not revoke an attached screenshot. Reinspection returns the same already-validated image or vision observation; the model is told that observation is supplied visual evidence, not user-typed text. Only evidence actually read in the turn may become an actionable citation. Search candidates are not evidence. Citation identities resolve through trusted source records rather than arbitrary model URLs. Parsed-text rune offsets are not PDF UTF-16 offsets; page precision is advertised only when verified. User clicks may introduce a same-course source into the current canvas, reusing matching material cards. Excerpt reuse and in-flight click coalescing include the complete read range and source fingerprint. Cards whose legacy identity omits the end offset are reused only when their full text matches the resolved excerpt. Navigation has a bounded 20-entry per-page return stack; model completion never moves the camera. Returning restores view state without reverting user edits or removing imported cards.

Course conversations retain the last eight completed course turns preceding the current saved turn, stopping at a selected-scope boundary. Their saved screenshots remain individually readable; text-only follow-ups automatically reread the two most recent distinct screenshots. Attachment hashes identify exact run input, not permission to discard course history when no new image is uploaded. Legacy selected-mode history keeps exact scope matching. Historical citation text grants no evidence authority. See [history decision](../decisions/0030-course-conversation-history.md).

Conversation version 2 stores context_scope, draft_attachments, per-turn attachments and citations. Version 1 remains readable and defaults to selected scope; its original bytes are backed up before migration. Version downgrades are rejected. Attachment bytes and metadata live under study-assets and travel through existing course sync. Canvas document version is unchanged.

Long Chinese-quoted passages immediately followed by a course citation are checked against that turn’s read text, ignoring whitespace and punctuation. Code examples do not create clickable evidence. A mismatch permits at most two correction attempts within the existing run budget, then fails explicitly. Historical citation links are removed before replay, because run-local evidence IDs may be reused. This check does not establish semantic correctness of paraphrases. Transcript labels show the verified read interval, not an inferred exact time for every sentence. Imported video playback waits for the canvas reference to be saved; navigation waits for player readiness, and playback errors never display authenticated URLs.

### Wire contract
All routes are under `/api/lectures/{id}/study-canvas`. `POST /attachments` uses multipart `image` (PNG) and `selection` (JSON bounds `[x,y,width,height]`, optional polygon point pairs, and source anchors). The response is the immutable attachment record (`id`, `resource`, `sha256`, `mime_type`, `width`, `height`, `selection`). `GET /attachments/{id}` reads that record; `/image` returns the verified PNG. Neither endpoint creates a canvas object.

`POST /sources/search` takes `{query}` and returns at most 12 candidates. `POST /sources/read` takes `{source, offset, limit}` and returns text plus original `path`, `lecture_id`, `id`, `fingerprint`, `representation`, `offset_unit: rune`, `offset`, `end` and optional `next_offset`. A search candidate has no evidence authority. Readable text has `availability: readable`; unsupported files retain their type and `unparsed` status. `POST /sources/resolve` takes `{source}` from saved evidence and revalidates its fingerprint and range. Source changes return HTTP 409; missing/out-of-course sources fail. Validated transcript evidence may additionally resolve to `video_path` and a time interval.

The run request adds optional `turn_id` (the saved current message, used to cut off retry history), `context_scope` and `attachments` alongside legacy `selection`, `allow_images` and `visuals`. A course tool allocates `eN` only after a successful bounded read; Markdown uses `[N](coursive://citation/eN)`. The final `citations` array contains `{id, number, label, source}` only for actual answer references. Persisted sources retain identity, fingerprint and range; text and search snippets are omitted and fetched again on resolve. The UI resolves these through the current message's stored table. `sources` remains available to legacy clients.

## Plan
Implement attachment and source interfaces in the daemon and both clients, then unified screenshot composition, course read tools and verified citations, followed by source navigation and return. Keep the existing legacy image path isolated. Reuse catalog, courseware search, transcript/note search, PDF extraction, media frame preparation and material imports.

Run relevant Go race, Node and Flutter tests and repository gates. Real model understanding and physical-device interaction are separate acceptance evidence.

## Evidence
Validation on 2026-11-08: Go full race suite and vet, Node 98 tests and syntax checks, Flutter full 277 tests and analysis (informational diagnostics only), and all six repository gates passed. The strict macOS native PDF selection/restore integration test passed with the installed renderer. [Snapshot tests](../../app/test/study_quick_question_test.dart), [conversation lifecycle](../../app/test/study_conversation_lifecycle_test.dart), [region manipulation](../../app/test/study_region_resize_test.dart), [navigation](../../app/test/study_source_navigation_test.dart), [daemon persistence and sources](../../daemon/internal/library/study_sources_test.go), [HTTP routes](../../daemon/internal/server/study_sources_test.go), and [agent evidence](../../agent/src/canvas-course-sources.test.mjs) provide deterministic evidence.

Android physical-device acceptance used an in-place ARM64 installation, the existing package/signature and a real local course containing six lectures. ADB touch and stylus events verified all four selection edges, with material and ink geometry unchanged. A large selection reserved the separate footer instead of covering selected content. A real screenshot question, two text-only image follow-ups and another follow-up after an application restart returned the expected visible text; the saved PNG hash remained identical. Cross-lecture references opened the actual local videos in the current canvas, and consecutive returns restored the original reading view without duplicating the videos. Installation checks preserved 185 affected file hashes and all seven referenced conversations. Final Android build 2026110809 also passed a fresh valid-quotation request, source-video reuse and return to the original PDF view.

Live acceptance exposed a first-load media publication race, authenticated playback URLs in error text, an overly narrow transcript time label, and reuse of a historical quotation under another run's citation ID. Playback waits for saved references and readiness; the UI displays a fixed error message; transcript evidence covers the verified read interval. A model/tool-loop regression checks quotation correction and history replay without old citation links. Repeating the failed real-model question then rejected the mismatched source and explicitly reported that the requested sentence was absent. These checks do not establish semantic correctness of arbitrary paraphrases or model answers.

macOS build 2026110804 was updated in place and launched with 92 affected user-file hashes unchanged. A real selection and its menu were observed, but native automation returned AXError.failure for edge dragging; the final video/history repair has not received a complete macOS window acceptance run. Windows/Linux device acceptance and Android physical-pen hardware behavior remain unverified; ADB stylus events do not prove pen pressure or palm rejection. Issue 28 remains open for that wider acceptance.
